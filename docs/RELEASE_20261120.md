## Revert the release while retaining history

After production synchronization, with a clean working tree and no later changes:

```powershell
git switch main
git pull --ff-only origin main
git revert --no-commit release/event-nfc-production-config-20261120
git revert --no-commit release/event-nfc-production-20261120
git revert --no-commit release/event-nfc-20261120
git commit -m "Revert event and NFC release while preserving database records"
git push origin main
```

This creates a new commit reversing the three release commits in order. It does not reset branches, force-push, drop tables or delete data. If later commits exist, review conflicts and preserve those changes instead of blindly reverting. To keep the feature branch aligned after a rollback, fast-forward it to the new main head and push it as well. A later merge commit may require reverting the merge with the correct parent; inspect the actual history first.
