## Entry 3 — Why no email is sent (SendGrid 401 on Render)

### Prompt Audit
All email functions stopped sending; Render log shows `Failed to send email "Reset your E-Balik password": HTTP Error 401: Unauthorized`.

### Findings
- SendGrid answers 401 when it rejects the API key itself (a bad sender gives 403). The code path is fine: the OTP was saved, SendGrid was called, the key was refused.
- No SendGrid key was ever committed to git (searched the working tree and full history), so it was not auto-revoked for leaking.
- The key in the local `Environment_Configs/backend/.env` was checked read-only against SendGrid (`GET /v3/scopes`, `/v3/verified_senders`, no email sent): **valid**, has `mail.send`, and the Gmail sender is verified. So the key set on Render differs from it (old or regenerated key, a typo) or was pasted with spaces, a line break or quotes.

### Edit Audit
- `Server/config.py`: new `_secret()` trims spaces, line breaks and wrapping quotes; `SENDGRID_API_KEY` and `SENDGRID_FROM_EMAIL` use it (a dashboard-pasted value with a trailing newline no longer fails). 871 tests pass. Not committed.

### Action for the user
On Render: service > Environment > set `SENDGRID_API_KEY` to the same key as the local `.env` (and `SENDGRID_FROM_EMAIL` to the verified sender), save, and let it redeploy.

### Database Audit
None.
