### Database Audit
**One migration was written. It was NOT executed: the project has no migration runner (it uses the Supabase SQL Editor), and no DDL or data write was performed from here.** To apply it, run `Server/manual_migrations/20261005_auction_hall.sql` in the Supabase SQL Editor. It is additive and idempotent (`IF NOT EXISTS`, `CREATE OR REPLACE`), runs in one transaction, and does not alter, drop or delete any existing table, column, policy or row.

- **New table `public.auctions`:**
  - Item snapshot: `found_item_id`, `item_reference`, `title`, `description`, `category`, `found_location`, `image_url`, `gallery_urls TEXT[]`.
  - Pricing: `starting_price`, `bid_increment`, `current_price`, `bid_count`, `highest_bidder_id`.
  - Timer: `starts_at`, `ends_at`, `original_ends_at`. Anti-snipe: `anti_snipe_enabled`, `anti_snipe_window_seconds`, `anti_snipe_extension_seconds`, `max_extensions`, `extension_count`.
  - Lifecycle: `status` (CHECK scheduled/active/ended/cancelled), `winner_account_id`, `winning_amount`, `ended_at`, `cancelled_at`, `cancel_reason`, `fulfillment_status` (CHECK awaiting_pickup/collected/forfeited), `fulfillment_updated_at`, `winner_notified_at`, `winner_email_mode`, `created_by`, `created_at`, `updated_at`.
  - Constraints: positive prices, window/extension limits (30 to 3600 s), `max_extensions` 0 to 50, and `ends_at > starts_at`.
  - Indexes: unique partial index `uq_auctions_one_live_per_item`, plus indexes on `(status, ends_at)`, `found_item_id`, `created_at` and `highest_bidder_id`.
- **New table `public.auction_bids`:** `bid_id`, `auction_id` (CASCADE), `bidder_account_id` (SET NULL), `amount`, `created_at`; two indexes.
- **New table `public.auction_comments`:** `comment_id`, `auction_id` (CASCADE), `account_id` (CASCADE), `body` (CHECK 1 to 500 characters), `is_hidden`, `hidden_by`, `hidden_at`, `created_at`; two indexes.
- **Foreign keys** to `found_items` and `user_profiles` use SET NULL or CASCADE, so the existing found-item delete RPC and the super-admin delete-user RPC keep working.
- **RLS:** `ENABLE ROW LEVEL SECURITY` on the three tables with no policies, so only the backend service key (which bypasses RLS) can read or write them.
- **New functions** (SECURITY DEFINER, `search_path` pinned, service role only, EXECUTE revoked from PUBLIC/anon/authenticated): `auction_place_bid(uuid, uuid, numeric)` and `auction_settle_due()` (rules described in `PROJECT_CONTEXT.md`).
- **Data semantics:** when an auction is awarded, the item's `found_items.status` becomes `auctioned` (no CHECK constraint exists on that column, and public lists and claims already require `unclaimed`, so sold items drop out automatically). A forfeited sale returns it to `unclaimed`.
- **Rollback (if ever needed):** `DROP FUNCTION public.auction_place_bid(uuid, uuid, numeric), public.auction_settle_due(); DROP TABLE public.auction_comments, public.auction_bids, public.auctions;`. Any `found_items` rows already set to `auctioned` would need `status = 'unclaimed'` restored.
